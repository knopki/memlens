# Правила работы в этом репозитории

Проект в фазе спецификации. Кода нет. Главный артефакт — `docs/spec/`.

## Порядок приёма нового утверждения

1. Записать дословно в [docs/statements.md](docs/statements.md) под новым ID `S-nnn` с датой.
2. Разложить по адресатам:
   - проверяемое поведение → `docs/spec/02-requirements.md`, новый `REQ-nnn`, статус `draft`;
   - рамка продукта → `00-overview.md` / `01-goals-nongoals.md`;
   - выбор с последствиями → `04-decisions.md` (или ADR в `docs/adr/`);
   - новый термин → `05-glossary.md`;
   - неясность → `03-open-questions.md`, блокирующий вопрос задать сразу.
3. Проверить конфликт с уже записанным. Конфликт → старое требование `disputed`, вопрос в
   `03-open-questions.md` с двумя вариантами. Молча перезаписывать нельзя.
4. Закоммитить: `spec: <что добавилось>`.

## Запреты

- Не придумывать требования, которых не было в утверждениях. Неизвестное = TBD или открытый вопрос.
- Не писать реализацию, пока требование не `accepted` или пока её не попросили явно.
- Не выходить за пределы директории проекта без разрешения.
- Не переписывать журнал утверждений: он источник, а не черновик.

там, где так принято в инструменте.
