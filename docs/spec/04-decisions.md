# Decision log

A small decision stays here. A decision that is expensive to change, or that needs an explanation
after six months, gets a separate ADR in [../adr/](../adr/).

| ID | Date | Decision | Context | Alternatives | Consequences |
|---|---|---|---|---|---|
| D-001 | 2026-11-04 | The specification is a set of markdown files in `docs/spec/` with a statement journal in `docs/statements.md`. | Statements come in portions. The project needs a trace from the customer words to a requirement, and a review by diff. | One `SPEC.md` file. An external tracker. | Small diffs in git. The project needs discipline with identifiers. No external tracker. |
| D-002 | 2026-11-04 | Each statement goes to the journal first, word for word. The meaning goes to the specification. | The meaning can drift. The original words give a second source for a conflict check. | Write the requirement directly, without the journal. | The same item appears two times: in the journal and in the requirement. The journal stays small and unchanged. |
| D-003 | 2026-11-04 | All documents and code comments use ASD-STE100 Simplified Technical English. The README also has a Russian and a Chinese version. | The customer selected STE for the entire project. STE gives short sentences and one meaning for each word. | Russian documents. Plain English. | Clear text for readers with a different first language. The writing needs a check against the STE limits. |
| D-004 | 2026-11-04 | The specification stays `draft` until the customer accepts an item. Code does not start before that, unless the customer asks for it. | A wrong requirement becomes expensive code. | Write code from a draft requirement. | The project waits for an agreement. The specification is correct before the code. |
| D-005 | 2026-11-04 | The stack is TypeScript on Node.js with pnpm workspaces. The packages are `@memlens/core`, `@memlens/cli`, and `@memlens/dsh-plugin`. The binary is `memlens`. The plugin identifier is `dsh-memlens`. | The customer selected the stack and the names. A DSH plugin needs TypeScript and Node.js. | A Rust core with TypeScript bindings. One package with subpaths. | One toolchain for three parts. The library and the CLI use `tsc`. The plugin uses `tsdown` and the `fixedExtension: false` setting. |
| D-006 | 2026-11-04 | Each package has a README in English, Russian, and Chinese. | The customer asked for the README in these three languages. Each package is a separate unit for a reader. | One README in the repository root only. Five languages, as the DSH guide recommends for a published plugin. | The same rule for each package. The check item `readme-five-langs` of the DSH guide stays open. See [Q-008](03-open-questions.md#q-008). |
| D-007 | 2026-11-04 | The scaffold uses the DSH plugin contract from the `dsh-plugin-guide` template. The contract has manifest version 1, a bundle patch file, display metadata, and peer dependencies on the harness packages. | The template is the verified starting point for a DSH plugin. | A hand-written manifest. | The plugin manifest passes `plugin-check`. A future host version can break the peer range. See [Q-005](03-open-questions.md#q-005). |
| D-008 | 2026-11-04 | Tool versions come from `mise.toml` as release lines: node 24, pnpm 12, and python 3.14. `mise install` gives a version inside each line, and `mise upgrade` takes the newest patch. The project does not commit `mise.lock`. | The customer installs the project tools with mise. A patch pin without a lockfile gives false precision and manual work at each release. | An exact pin of each patch with a committed lockfile. No pins and system tools. | One setup command for each clone. Security patches arrive with `mise upgrade`. A new patch can change behavior, and the checks catch it. The pnpm line must agree with `packageManager` in package.json. |
| D-009 | 2026-11-04 | The project keeps the check tools in `scripts/vendor/`: the STE linter under MIT and the DSH plugin checker under Apache-2.0 (`dist/` and `templates/` only). A check does not use a file outside the repository. | A check that searched the home directory for a skill failed on another machine and gave an unclear result. | Keep the search in the home directory. Copy the entire skill into the repository. Drop the checks. | One setup for each machine. The copies become stale after an upstream release, and `scripts/vendor/README.md` gives the update steps. |
