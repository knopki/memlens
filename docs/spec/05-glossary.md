# Glossary

One term has one meaning in all documents and in all code. This file is also the terminology base
for ASD-STE100 rule 1.8. The project approves each technical noun in this table.

| Term             | Meaning                                                                                                                                                                                   | Source                                       |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| memlens          | The project in this repository: a headless library, a CLI frontend, and a DSH plugin.                                                                                                     | S-002                                        |
| statement        | A customer sentence in the chat, recorded word for word with an identifier `S-nnn`.                                                                                                       | [0010](../adr/0010-process-stack.md) |
| requirement      | A testable sentence about the behavior of the system, with an identifier `REQ-nnn`.                                                                                                       | [README.md](README.md)                       |
| constraint       | A limit that comes from the customer or from the environment, with an identifier `C-nnn`.                                                                                                 | [01-goals-nongoals.md](01-goals-nongoals.md) |
| non-goal         | An item that the project does not do, with an identifier `NG-nnn`.                                                                                                                        | [01-goals-nongoals.md](01-goals-nongoals.md) |
| open question    | An item without an answer, with an identifier `Q-nnn`.                                                                                                                                    | [03-open-questions.md](03-open-questions.md) |
| journal          | The file [../statements.md](../statements.md). It keeps the customer words.                                                                                                               | [0010](../adr/0010-process-stack.md) |
| headless         | Without a user interface. Other programs start the function.                                                                                                                              | S-002                                        |
| library          | The package with the main function. It has no terminal interface and no plugin interface.                                                                                                 | REQ-001                                      |
| frontend         | The part that gives access to the library for a user or for a program. The project has a CLI frontend and a plugin frontend.                                                              | S-002                                        |
| CLI              | Command line interface. The user starts the function from a terminal.                                                                                                                     | S-002                                        |
| harness          | DeepSeek Harness (DSH), the agent harness that loads the plugin.                                                                                                                          | S-002                                        |
| plugin           | The package that the harness loads. The plugin gives access to the library from the harness.                                                                                              | REQ-003                                      |
| bundle           | The installable set of plugin rows for the harness. This package has one row.                                                                                                             | [0010](../adr/0010-process-stack.md) |
| bundle patch     | The file `cordis.patch.yml`. It adds the plugin row to the harness configuration.                                                                                                         | [0010](../adr/0010-process-stack.md) |
| row              | One plugin entry in the harness configuration. A row has an identifier and a module name.                                                                                                 | [0010](../adr/0010-process-stack.md) |
| workspace        | The unit of the harness that holds one directory. Its id has the form `ws_01H…`, and the rules of `[scope_default]` match it.                                                             | S-063, S-065                                 |
| localization     | The translation of the product text for one language. The scope of the term is open.                                                                                                      | Q-004                                        |
| STE              | ASD-STE100 Simplified Technical English, the writing standard of this project.                                                                                                            | S-003                                        |
| GRACE-lite       | The project standard for code markup: one module contract for each file and one region for each public or non-trivial entity.                                                             | S-011                                        |
| LDD              | Log driven development. The code writes short debug messages with key-value data. The messages act as observable contracts.                                                               | S-011                                        |
| native compiler  | TypeScript 7. The binary is `tsc`. The preview name was `tsgo`.                                                                                                                           | [0010](../adr/0010-process-stack.md) |
| note             | One curated fact in the log. The `note` event records it with a `body` and a `longform`.                                                                                                  | S-013, S-016                                 |
| body             | The short text of a note. It becomes a leaf of the tree. The target size is 384 characters.                                                                                                    | S-013                                        |
| longform         | The full document of a note. The size limit is 16 384 characters. It does not enter the tree.                                                                                                        | S-013                                        |
| retelling        | A short text that covers the notes below a node. The tree is a set of retellings.                                                                                                         | S-013                                        |
| tree             | The set of nodes above the notes. Each node is rebuildable from the log.                                                                                                              | S-013                                        |
| direction line   | One line of the map: the scope, the age or `active`, the count of notes, and the text.                                                                                                    | S-013, S-029, S-067                          |
| directions section | The one `<directions>` section of the slice. It holds the catalog. | S-013, S-104 |
| catalog | The tree over the scopes of a profile. A position holds one scope, and the content of the position is the top node of that scope. | S-013, S-104 |
| scope            | The unit of visibility and of write permission. A scope is a key in the events, and the store holds no record for it. A scope has a name only.                                                                     | S-013, S-033                                 |
| profile          | The unit that ties a set of scopes to one configuration section and one preset. The preset key `profile` names it.                                                                        | S-013, S-036, S-067                          |
| preset           | The second entry point of the plugin, `memlens/preset`. It gives the config of an agent preset. The key `profile` is mandatory.                                                           | S-013, S-067                                 |
| slice            | The text that the agent gets: one `<memory>` section with the policy text, `<directions>`, and `<here>`.                                                                                    | S-013, S-067                                 |
| snapshot         | One render of the slice from the store. The harness session history keeps its text as a runtime context message.                                                                          | S-013, S-046, S-067                          |
| store            | The memory storage. One store holds many profiles, scopes, and records. It has a version, one of two backends, and one index port.                                                        | S-013                                        |
| hide             | The op that removes a note from the view. The agent can hide a note.                                                                                                                      | S-013, S-016                                 |
| redact           | The op that removes the content of a note for good. Only the CLI or the GUI can redact.                                                                                                   | S-013, S-016                                 |
| amend            | The op that changes the content or the scope of a note. Only the CLI or the GUI can amend.                                                                                                | S-013, S-034                                 |
| proposed         | The state of a note that waits for a human decision. A subagent write and a write outside the profile give it.                                                                            | S-013, S-039                                 |
| nudge            | The reminder that the harness gives the agent to write a note. The `[nudge]` section gives the counts and the text.                                                                       | S-013, S-058                                 |
| writer           | The background task that makes the retellings in the form `parallel`, `batch`, or `auto`.                                                                                                 | S-013, S-116                                 |
| review           | The check of a note by a human. The `review` event records it, and `review_at` gives the date of the next check.                                                                          | S-013, S-016                                 |
| review period    | The number of days after a write when the record is due for review. The `review` section of the config gives it. | S-097 |
| index port       | The interface for the search. The implementation uses FTS5.                                                                                                                               | S-013                                        |
| «Линза» | The Russian name of the project. `memlens` joins memory and lens, and the lens gives the zoom into the tree. | S-013, S-072 |
| frontier         | The visible lines of the tree from the oldest level to the newest record. It tiles its range.                                                                                             | S-014                                        |
| level            | One row of the tree. A level has a fixed width, and one level covers 2^k leaves.                                                                                                          | S-014                                        |
| pair             | Two children that the node above joins.                                                                                                                                                   | S-014, S-030                                 |
| ruler            | The size measure of a retelling. The writer retries when the line does not become shorter.                                                                                                | S-014                                        |
| shrink check     | The rule that a retelling must be shorter than its source.                                                                                                                                | S-014                                        |
| compaction       | The process that builds the dirty nodes. The writer runs it in the background.                                                                                                            | S-013, S-051                                 |
| supersede        | A newer note replaces an older note in the view. It applies one time, at the first `live` state, and in one scope.                                                                        | S-014, S-016                                 |
| event            | One record of the log. It has `id`, `at`, `op`, and `scope`, and a payload for the op.                                                                                            | S-016                                        |
| op | The field that names an event: `note`, `amend`, `hide`, `redact`, `review`, `dismiss`, `node`, or `invalidate`. | S-016, S-101, S-135 |
| payload          | The fields of an event that belong to the op.                                                                                                                                             | S-016                                        |
| ULID             | The identifier format of an event. It is unique and it sorts by time.                                                                                                                     | S-016                                        |
| pos              | The ordinal of a real record entry into one scope. A transfer allocates a fresh destination position and leaves the old slot empty. | S-016, S-142 |
| target           | The field of an op that names the record or the proposal for a change. | S-016, S-101 |
| kind             | The class of a note: `decision`, `preference`, `fact`, `task`, or `note`. | S-016, S-065                                 |
| `live`           | The state of a record after a write with no proposal. | S-016, S-101 |
| `deleted`        | The state after redaction, including evidence from a sanitized note or amendment. | S-016, S-101 |
| sanitized form | A content event with `redacted: true` and its structural fields intact. Notes have empty body and null longform. Amendments clear present content fields. Nodes have empty summary and zero chars. | S-016, S-140, S-141 |
| at               | The time of an event in the log.                                                                                                                                                          | S-017                                        |
| ts               | The time of the write of a note.                                                                                                                                                          | S-017                                        |
| idem             | The idempotency key of a write. A second write with one value adds nothing.                                                                                                               | S-018                                        |
| projection       | The hot copy of the log: the records, the current node of each range, and the count of each scope. It holds the version of its schema.                                                    | S-126, S-127                                 |
| record           | One note after the projection: the copied fields, `recorded_at`, and the flags.                                                                                                           | S-020                                        |
| `record state`   | The lifecycle value of a record, in the order `live`, `hidden`, `deleted`. A `hide` and a `redact` raise it. | S-020, S-021, S-101 |
| node state       | The two tests of a node: `built` and `clean`. A node that fails a test is `dirty`.                                                                                                        | S-121, S-123                                 |
| hidden           | The state of a record after a `hide` event. The content stays.                                                                                                                            | S-020                                        |
| recorded_at      | The time of the note event in the log. It is equal to `at`.                                                                                                                               | S-020                                        |
| content_cleared  | The flag of a redacted record. An `amend` event changes no content of this record, and it still changes the scope.                                                                        | S-020, S-035                                 |
| superseded_by    | The field of a record that names the note that superseded it.                                                                                                                             | S-020                                        |
| pass             | One walk over the ordered events in the projection.                                                                                                                                       | S-020                                        |
| catalog scope    | The scope `__catalog__:<profile>`. It holds the nodes of one profile.                                                                                                                     | S-023                                        |
| dirty            | The state of a node that needs a build: it is not `built` or it is not `clean`.                                                                                                           | S-054, S-121, S-123                          |
| built | A node whose child references match its two halves. Null matches only an empty half. | S-121, S-123, S-137 |
| clean | A built node with clean child nodes, matching `input_rev`, and no invalidation. | S-121, S-135 |
| [redacted]       | The placeholder of the console and the view for a sanitized record. An event holds no such text.                                                                                          | S-023                                        |
| node             | One summary of the tree, recorded by a `node` event. It covers `2^level` positions for a level of 1 or more.                                                                                                          | S-025                                        |
| position         | One `pos` value in the geometry of the tree. A position with no live record is empty.                                                                                                     | S-025                                        |
| top node | The node at the top of the tree of a scope. It is one leaf of the catalog, and it gives the direction line of that scope. | S-100, S-104 |
| summary          | The text of one node. The target size is 512 characters and the limit is 640 characters.                                                                                                            | S-025                                        |
| input_rev        | The revision of the two children of a node at the build.                                                                                                                                  | S-025, S-100, S-121                          |
| leaf             | One record at the bottom of the tree. The tree holds no node of level 0.                                                                                                                  | S-028                                        |
| child | A node or live record in one half of a parent range. Null denotes an empty half. A change makes the parent dirty. | S-030, S-137 |
| budget           | The line limits of one profile: `here` and `directions`. The two are independent.                                                                                                | S-036, S-037, S-069                          |
| subagent mode    | The access of a subagent: `propose` writes and reports, `read` reads only, `off` has no tool and no slice.                                                                                | S-036, S-037                                 |
| here             | The tree slice of the active scope. The budget `here` limits this part.                                                                                                                | S-037                                        |
| directions       | The tree slice of the catalog. The budget `directions` limits this part.                                                                                                                  | S-037                                        |
| view             | The tiling of the frontier that the agent reads. Its cache key is `epoch`.                                                                                                                | S-040                                        |
| fold             | The pass that merges only until rendered lines fit the budget. Unready summaries give temporary lines, with no model call. | S-040, S-041, S-142 |
| line             | One item of the view: a record, a node, or a temporary line.                                                                                                                              | S-121, S-124                                 |
| revision | The latest input order within a non-empty range. A range with no live record gives null. | S-121, S-124, S-137 |
| tile             | One range of the view. A tile is a node or a record.                                                                                                                                      | S-040                                        |
| range            | The positions under one line: `2^level` positions from `start`.                                                                                                                           | S-121                                        |
| due              | The priority of a pair: `(total - (start + 2^(level+1) - 1)) / 2^level`. The fold and the rebuild use it.                                                                                 | S-040, S-041                                 |
| due filter       | The filter of `memory_find` that gives the records with a review date today or earlier. It is no priority. | S-071 |
| epoch            | The cache key of the view: a hash of `storeRev` and the built nodes.                                                                                                                      | S-040                                        |
| storeRev         | The version of the store content. A counter in SQLite and a fingerprint in JSONL.                                                                                                         | S-040                                        |
| cacheTtl         | The idle time after which a new snapshot replaces the text. The map gives a duration for a model glob.                                                                                    | S-042, S-067                                 |
| reason           | The cause of a `hide`, `redact`, `dismiss`, or `forget` event.                                                                                                                            | S-042, S-067                                 |
| `job`            | One computed dirty range that a writer attempts. It has no persistent queue row or lease. | S-051, S-142 |
| `backoff`        | The local retry wait after a failed attempt: ten, sixty, then three hundred seconds. A restart clears it. | S-051, S-142 |
| rev              | The order of the latest event that touches a range. It is no counter.                                                                                                                     | S-051, S-100, S-121                          |
| `ancestor`       | A node above another node in a tree. A change of a child makes each ancestor dirty.                                                                                                       | S-054                                        |
| `form`           | The shape of a run of the writer: `parallel`, `batch`, or `auto`. The key `writer.mode` gives it.                                                                                         | S-052, S-061, S-067                          |
| projection       | The hot copy of the log: the records, the current node of each range, and the count of each scope.                                                                                        | S-126                                        |
| scope key        | The key of a scope: two segments separated by a colon, and each segment holds lowercase text.                                                                                             | S-063, S-108                                 |
| scope | The set of records under one key. A scope has no record of its own: the first note of the key makes it, and that note is the description. | S-063, S-112 |
| scope name       | The second part of a scope key: lowercase letters, digits, the period, the underscore, the slash, and the hyphen.                                                                         | S-063                                        |
| wildcard         | The part `*` of a scope key. It matches any text of the kind or of the name.                                                                                                              | S-066                                        |
| address          | The pointer to one note or one range: `pos`, `pos-pos`, `scope#pos`, or `scope#pos-pos`.                                                                                                  | S-063                                        |
| active scope     | The scope of the current workspace, from the rules of `[scope_default]`.                                                                                                                  | S-063                                        |
| scope rule       | One entry of `rules`: a match type, a glob or an id, and a key.                                                                                                                           | S-063                                        |
| scope default    | The section `[scope_default]`: the rules and the fallback key.                                                                                                                            | S-063, S-065                                 |
| placeholder      | The part `{repo}` of a rule key. The resolver replaces it with a part of the match.                                                                                                       | S-063                                        |
| render form      | The address with a leading `#`. The renderer writes it, and the tool strips it.                                                                                                           | S-064                                        |
| hidden key       | A technical key of the store that the agent does not see. The catalog key is hidden.                                                                                                      | S-064                                        |
| runtime context  | The model-visible user-role message that the harness builds from `systemPrompt.context`. The session history keeps it.                                                                    | S-067                                        |
| policy text      | The static instruction text at the head of `<memory>`. The slice holds it whole.                                                                                                          | S-067                                        |
| `customPrompt`   | The template that replaces the slice template. The placeholders apply in it. The profile patch gives it. | S-042, S-094, S-103 |
| `customPromptAppend` | The text that takes the place of `{{append}}` in the template. The profile patch gives it. | S-042, S-094, S-103 |
| defaultProfile   | The profile of the general config. The preset `profile` wins over it.                                                                                                                     | S-067                                        |
| language         | The language that the prompt recommends to the agent for the notes. The default is `en`, because the FTS support is better.                                                               | S-067, S-068                                 |
| eight languages | The set `de`, `en`, `es`, `fr`, `ja`, `pt`, `ru`, and `zh`. The product, the README files, and the user documents hold the set, and English is the default and the fallback. | S-003, S-088, S-104 |
| agent preset     | The harness composition that selects the child plugins and the config of one agent.                                                                                                       | S-067                                        |
| profile patch    | The plugin row in `cordis.patch.yml` of a harness profile. It gives the config for the agents of that profile.                                                                            | S-067                                        |
| memory_note | The tool that saves one note. Its parameters are `body`, `longform`, `scope`, `kind`, `supersedes`, and `reviewIn`. | S-067, S-070 |
| memory_find      | The tool that searches the notes by words and gives the matching lines.                                                                                                                   | S-067                                        |
| memory_forget | The tool that hides records from the map. It takes `targets`, `scope`, and `reason`. | S-067, S-070 |
| memory_open | The tool that gives a note and its longform, or the non-empty child lines of a node. | S-067, S-137 |
| memory_review | The tool that gives the records due for review and sets a new review date. It takes `scope`, `reviewed`, and `reviewIn`. | S-070 |
| memory_scopes | The tool that lists the visible scopes. | S-070, S-112 |
| visible scope | A scope in the `scopes` list of the profile. A scope outside the list is invisible. | S-070 |
| write scope | The scope of a write with no `scope` field. The profile gives it. See Q-099. | S-070 |
| depth | The level of detail of a `memory_open` answer, from 1 to 4. It is no limit of the descent. | S-070 |
| working budget | The count of nodes that one `memory_open` call visits: 4096 at most. | S-070 |
| proposal line | The line in the report of the parent about one proposal of the child. | S-070 |
| UI core | The view models of the console in the core library. It holds no DOM, no transport, and no style. | S-077, S-080 |
| proposal | An ordinary write operation with the proposed modifier set to true. The projection ignores that operation. | S-101, S-142 |
| pending proposal | An operation with proposed true and no dismiss event that targets its id. | S-101, S-142 |
| tokenizer | The FTS5 search tokenizer of the index. It follows the key `language`. | S-101 |
| how-to | The section of the slice that holds the policy text and the append text. | S-102 |
| invalidation | The action that makes a node id unusable. An `invalidate` event holds the target ids, and a rebuild writes a new id. | S-133, S-134, S-135 |
| common prefix | The initial positions that have the same records and content before and after an import. | S-133 |
| build input | The exact child values that a job copies before its model call. The store compares them again before the append. | S-135 |
| replay cursor | The local position through which the projection processed the log. It is not an event order or a note position. | S-136 |
| total | One plus the greatest assigned position, or zero when no position exists. Records in the `hidden` and `deleted` states keep their positions. | S-137 |
| root range | The aligned range that starts at zero and covers every assigned position. Empty padding completes its power-of-two width. | S-137 |
| catalog position | The ordinal of a scope when the projection first encounters it in a profile. It does not change the scope tree range. | S-138, S-139 |
| jump | The sum of max(0, parent_level - 1 - neighbor_level) over the outer neighbors of a fold pair. The demo defines it. | S-142 |
