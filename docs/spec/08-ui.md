# UI

This file gives the full console in the chrome and the seven screens, and it gives the parts that the specification does not hold.

## Shape

The UI core is in the core library, and it holds no DOM, no transport, and no style. The view models
read the store through one port. See [REQ-417](02-requirements.md) to [REQ-419](02-requirements.md).

The command `memlens ui` hosts the full console. The plugin mounts the tab `Memory` on the session
page, and the tab shows one profile. See [REQ-420](02-requirements.md) to
[REQ-422](02-requirements.md) and [REQ-424](02-requirements.md).

## Chrome

| Region | Content                                                                                  |
| ------ | ---------------------------------------------------------------------------------------- |
| Header | The name, the profile, the backend, the dirty blocks, the meters of the two budgets, and the button "New record". |
| Rail   | The seven screens with the digits 1 to 7. The list of the scopes. The actions "Add", "Forget", and "Delete". |
| Footer | The path of the store, the scopes, the snapshot, and the writer.                          |
| Dialog | The form of a note: `body` with the counter of bytes, `longform`, `scope`, `kind`, and `supersedes`. |

## Screens

### Directions

| Region | Content                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| Banner | The session, the time of the materialization, and the next trigger.             |
| Scopes | One panel for each scope: the tag, the key, the first lines of the frontier, and the four counts. |
| Slice  | The text of the slice, with the head of the panel.                              |

The panel of the active scope gives the detail. The panel of a scope with no note stays in the list.

### Tree

| Region    | Content                                                                    |
| --------- | -------------------------------------------------------------------------- |
| Coverage  | One cell for each block, with the state built, queued, or outside the tree. |
| Frontier  | One line for each block: the address, the text, and the length.              |
| Inspector | The note, the document, the provenance, the relatives, and the actions.      |

A line of a block opens its two children, and a line of a note opens the note. The provenance gives
`id`, `ts`, `session`, `preset`, `kind`, and `refs`. The actions are "Open in the tree",
"Forget", "Delete", and "Copy the id".

### Catalog map

| Region   | Content                                                                    |
| -------- | -------------------------------------------------------------------------- |
| Timeline | One card for each session: the address, the scope, the date, and the line.  |
| Budget   | The use of the budget for each group of cards.                              |
| Ageing   | The rule of the shrink of an old card.                                      |

### Search

| Region    | Content                                                                    |
| --------- | -------------------------------------------------------------------------- |
| Query     | The field of the words and the button "Find".                               |
| Filters   | The scope, the kind, the start date, and the limit.                         |
| Hits      | The count, then one line for each match: the address, the kind, the text, and the date. |
| Inspector | The note and its document.                                                  |

The line of a match marks the words of the query.

### Review

| Region | Content                                                                          |
| ------ | -------------------------------------------------------------------------------- |
| Table  | The address, the date of the note, the text, the kind, the date of the review, and the actions. |
| Policy | The period of each kind.                                                          |

The action moves the date of the review. The actions of a note are "Reviewed", "Amend", "Supersede",
"Forget", and "Delete". See [REQ-423](02-requirements.md).

The policy gives 365 days for `decision`, `preference`, and `note`, 180 days for `fact`, and 7 days
for `task`. A note takes no eternal period, unless the user asks for one at the write.

### Proposals

| Region | Content                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| Table  | The address, the child session, the text, the scope, the age, and the actions.  |
| Rule   | The text of the rule.                                                           |

The actions are "Accept" and "Dismiss".

### Maintenance

| Region | Content                                                                        |
| ------ | ------------------------------------------------------------------------------ |
| Tiles  | The count of the notes, the count of the nodes, the blocks that wait for a merge, and the failed jobs. |
| Budget | The use of each budget.                                                         |
| Queue  | The job, the scope, the block, the level, the lease, the attempts, and the state. |
| Levels | The count of the nodes for each level, and the holes.                           |

## The tab `Memory`

The tab mounts in the slot `conversation.session.header`, and it gives each screen. It shows one profile,
and it gives no choice of the profile, because the session sets it. See [REQ-421](02-requirements.md) to
[REQ-424](02-requirements.md) and [REQ-446](02-requirements.md).

The dialog gives the kinds `decision`, `preference`, `fact`, `task`, and `note`. See [REQ-304](02-requirements.md).

## Remaining work

The transport of the full console is not specified.
