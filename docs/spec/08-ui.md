# UI

The console has one UI core and two hosts. The prototype `memory-console.html` shows the full
console. This file splits the prototype into the screens and marks the parts that the specification
does not hold.

## Shape

The UI core is in the core library. It holds the view models of each screen, and it holds no DOM and
no transport. The library imports no user interface package, so a view model gives data only. See
[REQ-007](02-requirements.md) and [REQ-417](02-requirements.md).

The view models read the store through one port. See [REQ-418](02-requirements.md).

`memlens ui` hosts the full console. The plugin mounts a simplified console as the tab `Memory` on
the session page, and the tab shows one profile. See [REQ-420](02-requirements.md) to
[REQ-422](02-requirements.md).

## Chrome

| Region | Content                                                       |
| ------ | ------------------------------------------------------------- |
| Header | The name, the profile, the backend, the dirty blocks, the slice budget, the button "New record". |
| Rail   | The seven screens with the digits 1 to 7, the scopes, and the actions. |
| Footer | The path of the store, the scopes, the snapshot, and the writer. |
| Dialog | The form of a new record: `body`, `longform`, `scope`, `kind`, and `supersedes`. |

The header gives the count of the dirty blocks and the meter of the slice budget. The rail lists
each scope with a colour. The footer gives the state of the store and of the writer. The dialog
writes one note. See [REQ-244](02-requirements.md) and [REQ-387](02-requirements.md).

## Screens

The prototype gives seven screens. Each screen reads the store and gives no write, unless the text
below says "write".

### Directions

This screen shows the state of the slice of the session.

| Region | Content                                                                     |
| ------ | --------------------------------------------------------------------------- |
| Banner | The session, the time of the materialization, and the next trigger.          |
| Cards  | One card for each scope of the profile.                                      |
| Slice  | The text that the agent reads: the policy text, `<directions>`, and `<here>`. |

The card gives the key, the description, and the first lines of the frontier. It gives the count of
the notes, the age, the size on the disk, and the size in the slice. The card of the active scope
gives the detail, and an old scope gives one line. See [REQ-297](02-requirements.md) and
[REQ-298](02-requirements.md).

### Tree

This screen shows the frontier of one scope and one selected record.

| Region    | Content                                                                 |
| --------- | ----------------------------------------------------------------------- |
| Coverage  | One cell for each block of the range, with the state built, queued, or outside the tree. |
| Frontier  | One line for each block: the address, the text, and the length.          |
| Inspector | The record, the document, the provenance, the relatives, and the actions. |

A line of a block opens its two children. A line of a record opens the record. The inspector gives
`id`, `ts`, `session`, `preset`, `kind`, and `refs`. The actions are "Open in the tree", "Forget",
"Delete", and "Copy the id". The delete action writes, and it needs the flag of the dialog. See
[REQ-217](02-requirements.md) and [REQ-323](02-requirements.md).

### Catalog map

This screen shows the catalog of the profile.

| Region   | Content                                                              |
| -------- | -------------------------------------------------------------------- |
| Timeline | One card for each session, with the scope, the date, and the line.     |
| Ageing   | The rule of the shrink of an old card.                               |

A fresh card gives its own line. An old card gives a coverage line, and the line opens the card
again. See [REQ-190](02-requirements.md) and [REQ-192](02-requirements.md).

The budget of the catalog is the budget `directions`, and the screen shows no budget of its own.

### Search

This screen finds records by words.

| Region    | Content                                                                 |
| --------- | ----------------------------------------------------------------------- |
| Query     | One field for the words, and one button.                                |
| Filters   | The scopes, the kinds, the start date, and the limit.                    |
| Hits      | One line for each match: the address, the kind, the text, and the date.  |
| Inspector | The record and its document.                                             |

The filter `due` gives the records that wait for review. The limit is 10 by default and 50 for each
scope. See [REQ-388](02-requirements.md), [REQ-314](02-requirements.md), and
[REQ-315](02-requirements.md).

### Review

This screen gives the records that wait for a human.

| Region | Content                                                                       |
| ------ | ----------------------------------------------------------------------------- |
| Table  | The address, the text, the kind, the date of the review, and the action.       |
| Policy | The period of each kind.                                                       |

The action moves the date of the review. The periods are 365 days for `decision`, `preference`, and
`note`, 180 days for `fact`, and 7 days for `task`. See [REQ-340](02-requirements.md) and
[REQ-365](02-requirements.md).

### Proposals

This screen gives the records with the state `proposed`.

| Region | Content                                                                    |
| ------ | -------------------------------------------------------------------------- |
| Table  | The address, the child session, the text, the scope, the age, and the action. |
| Rule   | The rule of a proposal.                                                     |

The action accepts or dismisses one proposal. A new proposal is a new note only. An unaccepted
proposal gets a `dismiss` after 30 days. See [REQ-361](02-requirements.md) and
[REQ-362](02-requirements.md).

### Maintenance

This screen shows the state of the tree and the queue.

| Region | Content                                                                       |
| ------ | ----------------------------------------------------------------------------- |
| Tiles  | The count of the records, the count of the nodes, the dirty blocks, and the failed jobs. |
| Budget | The budget `here` and the budget `directions`, each against its use.            |
| Queue  | The job, the scope, the block, the level, the lease, the attempts, and the state. |
| Levels | The count of the nodes for each level, and the holes.                          |

The tree is a cache, and a read of the memory does not wait for it. See
[REQ-022](02-requirements.md) and [REQ-204](02-requirements.md).

## The tab `Memory`

The tab mounts a part of the screens, and it shows one profile. The profile comes from the session.
The tab shares the UI core with the full console. See [Q-106](03-open-questions.md) and
[Q-107](03-open-questions.md).

## The prototype and the specification

| Item              | The prototype                                   | The specification                          | Decision        |
| ----------------- | ----------------------------------------------- | ------------------------------------------ | --------------- |
| Budgets           | Four parts: `how-to`, `directions`, `map`, `here`. | Two: `here` and `directions`.           | Drop `how-to` and `map`. |
| Scope state       | The tag `archived`.                             | No archived state.                         | Drop.           |
| Kinds             | `procedure` and `question`.                     | `decision`, `preference`, `fact`, `task`, `note`, and `card`. | Drop the two. |
| `supersedes`      | An `id` of a record.                            | A `pos` or an `addr`.                      | Drop the `id` form. |
| Provenance        | The field `hash`.                               | No hash field.                             | Drop.           |
| Review actions    | `supersede` and `done`.                         | The `review` event moves the date only.    | Drop the two.   |
| Import            | A manifest with the hash of a block.            | A union by `id`.                           | Drop.           |
| Store version     | `epoch` and `logGen`.                           | `storeRev`.                                | Show `storeRev`. |
| Scrub             | `needsScrub`.                                   | No scrub step.                             | Drop.           |

The dialog gives the kinds `decision`, `fact`, `preference`, `procedure`, and no `task`. The
specification gives five kinds, and the dialog shows `decision`, `preference`, `fact`, `task`, and
`note`. See [REQ-304](02-requirements.md).
