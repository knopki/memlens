# UI

The standalone console and the plugin page supply seven screens.
The [console model contract](../../packages/core/src/domain/console.ts) owns the shared read models.
The [client contracts](../../packages/ui/src/client.ts) own the screens, the forms, the note inspector, and the theme choice.
The [message contract](../../packages/ui/src/i18n.ts) owns the text of each language.
The [host contract](../../packages/cli/src/ui.ts) owns HTTP, action validation, and the delete policy.

## Hosts

The command `memlens ui` hosts the console with its own styles.
The CLI builds the browser client as a separate bundle and serves it through a local HTTP server.
The flags `--port` and `--allow-delete` select the port and permit confirmed deletion.
The console answers a profile that the base file does not name with the default profile values,
so no configuration state fails a request. The switcher of the console always holds the default
profile name.

The plugin mounts the page `Memory` as one keyed entry of the slot `main`.
The entry key is `memlens`.
The plugin mounts one row of the slot `sidebar.panellist` with the same id, so the left side panel
holds the entry that opens the page.
The label of the row comes from the locale service, and the Russian label is `Память`.
The page belongs to no session. It reads the profiles of the base file and switches between them.
The switcher always holds the default profile name.
A profile that the base file does not name uses the default values of that profile, so the page
answers and holds no failure. The base file may state no profile at all.
The page has no directory, so its fallback scope key is the last key of the source list,
`project:misc`.

The plugin mounts the state tab of one session as one entry of the slot `conversation.view`.
The entry id is `memlens`, and the label comes from the locale service.
The tab shows the saved slice of the session scope, the profile name, and the available scopes.
The tab holds no screen control.
No slot takes a kind for a tab.

The console has a left side panel, and the session
surface holds the slice of the session scope only. The rows [REQ-549](archive/02-requirements.md) to
[REQ-553](archive/02-requirements.md) are `accepted`.

Both hosts share one component layer in `packages/ui`.
A component holds no style, no transport, and no address.
`memlens ui` supplies its own shell and its own styles.
The plugin supplies the harness surfaces: the slot, the theme tokens, and the locale service.
The plugin supplies its own style where the harness has no component.
The plugin imports no harness client package and no iframe.

The standalone host supplies its own backend.
The plugin console uses the harness Remote service for its data calls.
The session selects one profile. The tab gives no profile selector, and the page gives the
selector of each profile of the base file.
See the [core entry contract](../../packages/core/src/index.ts) and [REQ-028](archive/02-requirements.md).

Both hosts must give the note actions: reviewed, amend, supersede, forget, and delete.
See [REQ-423](archive/02-requirements.md).
Proposal approval must apply the ordinary operation and close the proposal in one logical transaction.
See [REQ-361](archive/02-requirements.md).
The console must give compaction inputs and publish the answers through store validation.
See [REQ-459](archive/02-requirements.md).

## Screens

- The overview shows one card for each visible scope and the assembled slice below the cards.
- The tree screen shows the slice lines of the selected scope. A range line opens its text and its two children. A note line opens the record.
- The catalog screen shows the direction lines of the visible scopes with the directions budget. A range line opens its two halves, and a line over one scope opens the tree of that scope.
- The search screen finds notes in the selected scope or in every visible scope. The scope filter opens on the selected scope.
- The review screen lists the due notes of the selected scope, with the five note actions. A second section lists the nearest notes with a later review time. A kind filter narrows both sections, and the second section states its count before the cap.
- The proposals screen lists the pending proposals with accept and dismiss.
- The maintenance screen shows the build candidates, the line budgets, and the compaction job.

The tree screen shows the frontier of the model, so a range line and the notes inside that range never appear together.
See the [console contract](../../packages/core/src/domain/console.ts).
An amendment form changes the body, the document, the scope, the kind, and the supersedes of a note.
See the [notes contract](../../packages/core/src/store/notes.ts) for the scope transfer, the kind change, and the supersedes of an amendment.
A compaction job without a merge input states that fact and opens no answer form.
See [REQ-518](archive/02-requirements.md).

## Address and history

The console keeps the screen, the profile, the scope, the open note, and the search filters in the
address of the page. A reload and the browser buttons return to that place.
See the [client contract](../../packages/ui/src/client.ts) and the
[route contract](../../packages/ui/src/route.ts).

## Text and theme

The interface text supports the eight languages of the DSH set.
The language list gives each name in its own words, and a language without a text gives English.
See the [i18n contract](../../packages/ui/src/i18n.ts).
The theme choice is light, dark, or system, and the page follows the system setting while the choice is system.
The choice survives a reload.
See the [client contract](../../packages/ui/src/client.ts).

The standalone console holds no compaction and no harness session. It states no compaction state and no session snapshot state.
See the [client contract](../../packages/ui/src/client.ts).

## Data boundaries

The UI core holds no DOM, transport, or style. It reads the store through `StorePort`.
The standalone host supplies HTTP. The plugin uses the harness Remote service for console calls.
A component reads the store through `StorePort`. A shell supplies the one transport of its host.
The browser client imports core types only. Its bundle holds no backend implementation.

The [model contract](../../packages/core/src/domain/console.ts) owns empty scopes, the frontier lines, and stable read revisions.
The [form contract](../../packages/ui/src/client.ts) owns scope creation through its first note.
The standalone console reads current store data. It does not create a harness snapshot.

## Host runtime state

The plugin Remote status method supplies the session, the materialization time, the next refresh,
and the saved snapshot state. The port carries it as the optional `runtime` capability.
The standalone host gives no runtime, so its console shows no such panel.

The compaction view derives candidates from the dirty ranges and the local runtime state.
It reads no stored work list.
It shows the model route, the last pass time, and the next timer time.
It also shows the attempts, the active builds, the backoff, the failures, the dirty count, and the
last error. A compaction of that host gives these fields.
A restart resets each local count, time, and error.
The screen also shows the local worker journal. The host log mirrors each journal entry.
One entry is a pass, a retry, an error, or a model call of one pass.
The screen reads the runtime state again every five seconds while a human looks at it. The live
read takes the status method only, so it reloads no view and holds no action.
Leaving the screen clears the read. An answer of a cleared read writes no state.
The screen formats each time and date in the local zone of the browser.
