# 0002. Stack and build

Status: accepted

## Context

TypeScript 7 on Node.js with pnpm workspaces. The three packages have entry points and a build. The tool versions come from `mise.toml`, and the packages use dev dependencies for the tools that they run.

## Decisions

| ID | Date | Decision | Context | Alternatives | Consequences |
| --- | --- | --- | --- | --- | --- |
| D-005 | 2026-11-04 | The stack is TypeScript on Node.js with pnpm workspaces. The packages are `@memlens/core`, `@memlens/cli`, and `@memlens/dsh-plugin`. The binary is `memlens`. The plugin identifier is `dsh-memlens`. | The customer selected the stack and the names. A DSH plugin needs TypeScript and Node.js. | A Rust core with TypeScript bindings. One package with subpaths. | One toolchain for three parts. The library and the CLI use `tsc`. The plugin uses `tsdown` and the `fixedExtension: false` setting. D-011 replaces the build tools. |
| D-006 | 2026-11-04 | Each package has a README in the eight languages of the DSH set. | The customer asked for the README in these three languages. Each package is a separate unit for a reader. | One README in the repository root only. Five languages, as the DSH guide recommends for a published plugin. | The same rule for each package. |
| D-007 | 2026-11-04 | The scaffold uses the DSH plugin contract from the `dsh-plugin-guide` template. The contract has manifest version 1, a bundle patch file, display metadata, and peer dependencies on the harness packages. | The template is the verified starting point for a DSH plugin. | A hand-written manifest. | The plugin manifest passes `plugin-check`. A future host version can break the peer range. See [Q-005](03-open-questions.md#q-005). |
| D-008 | 2026-11-04 | Tool versions come from `mise.toml` as release lines: node 24, pnpm 12, and python 3.14. `mise install` gives a version inside each line, and `mise upgrade` takes the newest patch. The project does not commit `mise.lock`. | The customer installs the project tools with mise. A patch pin without a lockfile gives false precision and manual work at each release. | An exact pin of each patch with a committed lockfile. No pins and system tools. | One setup command for each clone. Security patches arrive with `mise upgrade`. A new patch can change behavior, and the checks catch it. The pnpm line must agree with `packageManager` in package.json. |
| D-011 | 2026-11-04 | The project builds with TypeScript 7, the native compiler. The preview name of the compiler was `tsgo`, and the binary is `tsc`. The core builds with `tsc` and writes JavaScript and declarations. The CLI and the plugin build with esbuild as one bundle. The plugin gets its declarations from `tsc --emitDeclarationOnly`. biome lints and formats. vitest runs the tests. prek runs the git hooks. | The customer selected the toolchain. The native compiler type checks and writes declarations, so one tool covers the core. A bundle is necessary for the CLI binary and for the plugin entry. | tsc 5 with tsdown. eslint with prettier. husky with lint-staged. | One compiler for the types. esbuild writes no declarations, so the plugin runs `tsc` for them. The plugin bundle keeps the packages external. |
| D-012 | 2026-11-04 | A tool that the packages run comes from npm as a dev dependency, so the lockfile pins it. mise holds the machine toolchain: node, pnpm, python, and prek. | biome was a mise tool. The pre-commit hook then started a mise install and needed the network. The lockfile gives one pinned version for each package. | Keep biome in mise. Put every tool in mise. Put every tool in npm. | The hook runs offline from `node_modules`. The lockfile pins each npm tool. mise holds the tools that npm does not distribute. |
