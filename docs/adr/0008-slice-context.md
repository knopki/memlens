# 0008. Slice and context

Status: accepted

## Context

The slice is one `<memory>` block with the policy text, the directions, and the here part. The plugin gives the text through `systemPrompt.context` and reads it from the session history. The agent tools read and write the records.

## Decisions

| ID | Date | Decision | Context | Alternatives | Consequences |
| --- | --- | --- | --- | --- | --- |
| D-015 | 2026-11-04 | The tree is a cache over the notes. The view is a deterministic function of the notes, the built nodes, and the store version. The slice is a materialized snapshot, and the `sessions` record points to it. | The customer gave the cache rule and the snapshot rule. A deterministic view stays testable and cheap to rebuild. | Build the text on each turn. Keep the text in the session log. | A rebuild gives the same text. The snapshot has an id, so a reader can name the exact slice. D-050 and D-052 replace this decision. |
| D-050 | 2026-11-04 | The store of memlens holds no snapshot. The plugin renders the text from the store at each trigger, and it gives the same text until the next trigger. | S-046 gives the render. A snapshot is a view of the store, and a second copy of it costs storage and a redact path. | Keep a copy of the text in the store of memlens. Render the text at each assembly. | One store, one truth. A `redact` cleans the store, and the next trigger renders the text again. |
| D-051 | 2026-11-04 | The snapshot is a cache of the plugin. The harness receives the text through `systemPrompt.context`, and the session history keeps the copy. | S-044 asks why the slice belongs to the plugin. The store of memlens renders it, and DSH holds it in the session. | Keep the text in the store of memlens. Ask the harness for the text on each build. | The harness holds the copy in the session. The store of memlens stays the source of the slice. |
| D-052 | 2026-11-04 | The plugin reads the text of the last snapshot from the session history and gives that text at each assembly. A `redact` changes no snapshot in the history. | DSH runs the provider at each assembly, and it writes the snapshot into the history only at a change. A render at each assembly makes a second snapshot. | Keep the text in the memory of the plugin. Keep the text in the store of memlens. | One snapshot for each trigger. The copy stays in the log of the session after a `redact`. |
| D-056 | 2026-11-04 | The compression works on `<directions>` first, then on `<here>`, and it cuts no policy text. A part above 1.5 times its budget loses the oldest `<here>` lines, and one line `#<a>-<b> omitted (N lines, compacting)` takes their place. `memory_open` gives the range. | A slice above the limit costs tokens at each assembly. A cut keeps the newest text, and the address keeps the old text reachable. | Cut the newest lines. Cut a whole block. Truncate the text with no marker. | The `<here>` part stays at 1.5 times the budget or below. A `<directions>` part above its limit keeps its lines. The agent sees one line about the gap. The old text costs one more call of the tool. |
| D-057 | 2026-11-04 | The nudge is one line after the frozen slice, so the cached prefix stays put. A write creates no record when a live note of the same scope holds the normalized `body`, `longform`, `kind`, and `review_at`, and the write has no `supersedes`. In the mode `expensive`, a long turn demands a write before its end. | A nudge inside the slice changes the cached prefix at each turn. A fuzzy dedup would hide a correction. | The nudge inside the slice. A semantic dedup. No dedup. | The cache stays warm. A repeated write costs one call and no record. A correction with one changed word makes a new note. |
| D-058 | 2026-11-04 | The default text of the nudge names no unit: `[memory] {n} steps since the last record. Anything durable: a decision, a correction, a preference, a failed attempt and its cause?` | One text serves each mode, and `{n}` holds tool calls in `tools`, turns in `turns`, or steps in `expensive`. A text with `tool calls` lies in two modes. | Keep `{n} tool calls` and ask the profile to set `text`. Drop `{n}`. | The default text is true in each mode. A profile can still give its own text. The default keeps `{n}`. |
| D-064 | 2026-11-04 | The slice goes to `systemPrompt.context`, not to a system prompt section. The plugin registers one context for each agent at `agent/created`, with `required: true` and the order 220. The text stays the same until a trigger. The plugin reads it from the session history. It renders a new one at a fresh session, a compaction, and an idle time above the TTL. A process restart gives the same text. | A section change invalidates the whole cached prefix. `systemPrompt.context` is a durable user-role snapshot after the saved history, and the harness re-logs it only at a change or after compaction. The AGENTS.md loader uses `agent/pre-step` messages, not `agent.inject`. In 0.2.1-rc.5 `getContextOrder` names seven built-in contexts only, and `agentPreset` and `cwd` are on the session meta. | A system prompt section. `agent.inject` with a user message. A context order from `getContextOrder` with the plugin name. | The context survives a compaction and a restart. The plugin does not touch the system prompt. The order 220 puts the memory after the web surface context. The host gives no order slot for a new name. |
| D-066 | 2026-11-04 | The agent surface is `memory_find`, `memory_open`, `memory_note`, and `memory_forget`. `memory_review` stays. `memory_note` takes `body`, `longform`, `scope`, `kind`, and `supersedes`, and it takes no `reviewIn`. The slice is one `<memory>` block with the policy text at the head, then `<directions>`, then `<here>`. A direction line gives the scope, the age or `active`, the count of notes, and the description. `memory_find` gives the matching lines with their addresses. `memory_open` of a node gives its two child lines. | The customer gave the tool names and the slice text. The old surface used `write` and `hide`. The `<how-to>` tag is absent from the new text. The tiling example is a complete cover of the range. | Keep `write` and `hide`. Keep the `<how-to>` tag. Return the raw records of a range from `memory_open`. | The old names leave the tool list. The policy text is not a tag. A review date comes from the `review` event. A nested block opens into two lines. D-070 replaces this decision. |
| D-068 | 2026-11-05 | The descent of `memory_open` stops at a working budget of 4096 visited nodes and at an answer of 24 KiB. `depth` gives the level of detail from 1 to 4, and it is no limit of the descent. A range that the budget stops comes back with `needsExpansion` and its `label`. | S-070 names `depth` as the level of detail and names the working budget as the limit of the descent. A silent gap loses records. | A depth limit on the search for clean parts. No reopen of the stopped range. | A deep tree gives an addressable range, and one call opens it again. REQ-329 to REQ-337 hold the rules. |
| D-069 | 2026-11-05 | A subagent write is always `proposed`. The proposals of one child collect under its session id, and the report of the parent gets one line for each. A human accepts or dismisses a proposal in the console. An unaccepted proposal gets a `dismiss` after 30 days, and the event log keeps its content. | S-070 gives the delivery and the fate of a proposal, and it gives no accept tool. | An accept tool for the agent. An automatic accept at the session end. | An agent accepts no own proposal. The parent accepts with a normal `memory_note`. A dismissed proposal stays in the log only. REQ-353 to REQ-363 hold the rules. |
| D-070 | 2026-11-05 | The agent surface is `memory_find`, `memory_open`, `memory_note`, `memory_forget`, `memory_review`, and `memory_scope`. A write takes `reviewIn`. A note and a forget in a scope outside `scopes` give a proposal, and a review gives `NotAllowed`. `amend`, `redact`, `accept`, and `dismiss` stay in the CLI and the GUI. | S-070 gives the six tools and the table of the permissions. | The surface of D-066: five tools, and no `reviewIn` on the write. | Q-094 and Q-096 hold the two open fields of the write and of the forget. REQ-293 to REQ-352 hold the surface and the errors. |
