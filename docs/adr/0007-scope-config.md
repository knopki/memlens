# 0007. Scope and config

Status: accepted

## Context

A scope is a key in the events, and the store holds no record for it. A profile lists scopes and gives the budgets. The plugin config merges three layers.

## Decisions

| ID | Date | Decision | Context | Alternatives | Consequences |
| --- | --- | --- | --- | --- | --- |
| D-017 | 2026-11-04 | The plugin package has two entry points: `.` and `./preset`. A profile ties to a preset. The configuration merges the main part and the preset part. | The customer gave the two entry points and the merge. An agent preset needs its own settings. | One entry point with a mode flag. A separate package for the preset. | One package serves both uses. D-065 replaces the merge rule. |
| D-042 | 2026-11-04 | The project does not adopt the scope registry. A scope has no event of its own and no label. The store keeps the key in the events of the records. | The registry has five ops and a merge rule for two fields. S-033 keeps the key only, and the first note gives the text. | The append-only `scopes.jsonl` with five ops. A registry in the configuration with the same five ops. | No scope event in the log. No `owner` error at an import. A scope exists because a record names its key. |
| D-043 | 2026-11-04 | A wrong key of a scope changes by an `amend` of the record. The model has no alias map. | S-033 refuses the alias as a second name for one scope, and the customer gives `amend` for a wrong key. | An alias map in the configuration. A rewrite of the events of the old key. | One name for one scope. A value stays in the event. A full rename costs one amend for each record. |
| D-044 | 2026-11-04 | An `amend` moves a record to the key in its `scope` field, and it does so for a record with `content_cleared` too. The tree keeps its geometry. | A wrong key must leave the catalog of the scope that it does not belong to, and an erased record must not keep it. | A separate op `move`. A rewrite of the events of the old key. | The op list keeps seven events. The `pos` and the summaries stay. The cards of both scopes pick up the change. |
| D-045 | 2026-11-04 | The configuration is a TOML file with a `store` section and one `[profile.<name>]` section for each profile. The CLI store path comes from `--store`, then `MEMLENS_STORE`, then the file. | One file must hold the store settings and the profiles, and a script must change the path without an edit of the file. | A YAML file. One file for each profile. The environment only. | One file for the store and the profiles. A flag wins over the environment, and the environment wins over the file. |
| D-046 | 2026-11-04 | The configuration sets no total budget. The budget `here` limits the tree of the active scope, and the budget `directions` limits the tree of the catalog. | Two parts of the slice need one limit each, and a total hides which part spends the bytes. | One total budget for the slice. Three budgets with `slice`. | A user sets the detail of the current project and the size of the map apart. No cap covers both. |
| D-047 | 2026-11-04 | The subagent mode sets the access of a subagent. `propose` writes proposed notes and reports to the parent, `read` gives no writing tool, `off` gives no tool and no slice. | A profile must give a subagent less than the parent, and one mode names the level. | One rule for each subagent. A permission for each tool. | The parent keeps the reports in `propose`. A subagent in `off` spends no slice bytes. |
| D-060 | 2026-11-04 | A scope key has the form `kind:name`. The kind is `project`, `global`, `agent`, `user`, `topic`, `task`, or `import`, and the name is lowercase. The active scope comes from the ordered rules of `[scope_default]`, and the first match wins. A repository with no match gets the `default` key. The visibility of a profile is its `scopes` list. | One grammar lets a profile name a family of keys with one wildcard. The rules keep the active scope out of each session. | A free-form scope string. One scope for each workspace in the plugin settings. No rules, and one scope for each repository. | A write outside the profile waits for a human. A wrong rule gives the default scope. The grammar covers the keys of the agent. See D-061. |
| D-061 | 2026-11-04 | The scope grammar covers the keys that the agent sees. A technical key of the store stays outside it, and the catalog key `__catalog__:<profile>` is hidden. The address holds no `#`, the renderer adds it, and the tool strips it. `workspace:<id> → key` is a rule. | The catalog key is internal, and a visible key costs tokens. A display prefix keeps the slice readable, and the tool accepts the previous copy. | A visible catalog key. A `#` at the tool. | The agent never names the catalog key. A copied address works with the `#` and without it. Each call runs the rules. |
| D-062 | 2026-11-04 | The `pos` of an address is the ordinal in the scope. A kind is a label, and it changes no behavior. The `[scope_default]` section holds `rules` and `default`, and it holds no profile key. | A count in the scope would renumber a record that changes its scope, and the address must stay. The kinds name a family of keys, and no rule uses a kind. | A count in the scope. A rule for each kind. A profile key in the section. | A moved record keeps its address. Two scopes with different kinds behave in one way. The preset gives the profile (Q-020). |
| D-063 | 2026-11-04 | The part `*` of a scope key stands in the kind or in the name, and it matches any text of that part. The key `*` matches each scope. The store lowercases a scope key before the write. | A profile that lists a family of scopes needs one form, and the kind can be part of the family. A key with a capital letter must not make a second scope. | A wildcard in the name only. A refusal of a key with a capital letter. | One key covers a whole family, and a case typo adds no scope. |
| D-065 | 2026-11-04 | The plugin config is a deep merge of three layers: the memlens TOML file, the profile patch in `cordis.patch.yml`, and the agent preset patch. The patch wins over the TOML, and the preset wins over the profile. Arrays replace. The general layer gives `defaultProfile`. The preset must give `profile`. The plugin id is `memlens`, and the preset id is `memlens/preset`. | The customer gave two entry points and a deep merge. The preset names the profile. The plugin needs the store path, the writer, the nudge, the language, and the cache TTL. The TOML file gives the store backend, so the plugin reads it as the base. The `language` key gives the language that the prompt recommends for the notes. The default is `en`, because the FTS support is better. The flag is a CLI setting and the patch is a plugin setting. The two programs have separate chains. | One file for the harness and the CLI. A merge in the host. Arrays that concatenate. | The CLI reads the TOML file. The harness reads the patch layers. A preset without `profile` fails at load. The plugin takes the patch first, then `MEMLENS_STORE`, then the TOML file. The CLI takes `--store` first. |
