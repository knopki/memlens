# @memlens/dsh-plugin

[English](README.md) | [中文](README.zh.md) | [Deutsch](README.de.md) | [Español](README.es.md) | [Français](README.fr.md) | 日本語 | [Português](README.pt.md) | [Русский](README.ru.md)

## 概要

`@memlens/dsh-plugin` は、各 DeepSeek Harness エージェントに memlens のメモリを与えます。ホスト
エントリは共有ストアを 1 つ開きます。ホストエントリは各稼働中エージェントにメモリコンテキスト、
メモリツール、ナッジを与えます。ホストエントリはまた、古いノートを要約行にまとめるバックグラ
ウンドワーカーを開始します。プリセットエントリは、1 つのエージェントプリセットがそのメモリプ
ロファイルを選べるようにします。パッケージはハーネスの Web ページにコンソールをサイドパネルと
セッションタブとしてマウントします。

<a id="use-this-package"></a>
## このパッケージを使う

### インストールする

使うプロファイルにパッケージを追加します。

```sh
dsh plugin --profile web add @memlens/dsh-plugin
```

フラグ `--profile` はプロファイルを指定します。例えば `web` や `desktop` です。コマンドは残りの
引数を、プロファイルディレクトリの pnpm に転送します。

ホストエントリは LLM サービスを必要とします。ワーカーがコンパクションの呼び出しをそれ経由で
送るためです。ホストエントリはワークスペースサービスを任意として宣言します。

### エントリ

- ホストエントリはモジュール `@memlens/dsh-plugin` です。バンドルパッチは行 `memlens` を挿入し、
  プロファイルはその行 id を上書きします。
- プリセットエントリはモジュール `@memlens/dsh-plugin/preset` です。エージェントプリセットは行
  `memlens/preset` としてこれをマウントします。

ホストエントリは名前 `memlens` を宣言し、プリセットエントリは `memlens/preset` を宣言します。

#### ホスト行

```yaml
- insert:
    - id: memlens
      name: "@memlens/dsh-plugin"
```

#### プリセット行

```yaml
- id: memlens/preset
  name: "@memlens/dsh-plugin/preset"
```

キー `profile` がない場合は、プロファイル `default` を選びます。

### 設定する

行のテーブル `config` は、そのレイヤの設定を保持します。ホスト行の例です。

```yaml
- insert:
    - id: memlens
      name: "@memlens/dsh-plugin"
      config:
        defaultProfile: work
        budget:
          here: 40
        compaction:
          provider: deepseek-official
          model: deepseek-flash
```

プリセット行の例です。

```yaml
- id: memlens/preset
  name: "@memlens/dsh-plugin/preset"
  config:
    profile: work
    budget:
      here: 30
```

各キーは任意です。拒否された値は空のレイヤになります。そのため、不正な行はどのセッションも変
更しません。

プリセットはプラグインパッチを上書きします。プラグインパッチは基本プロファイルを上書きします。
プリセットのキー `profile` はプロファイル名を選びます。プリセットはコンパクションのキーもストア
のキーも受け付けません。

基本ファイルは、プラットフォームの構成ディレクトリの `config.toml` です。ファイルがない場合は、組み込みの
フォールバックが適用されます。プロファイル `default`、スコープ `*`、バジェット 20 と 10、スコー
プ `project:misc` です。ファイルのセクションがない場合は、その既定値を使います。基本ファイルが
不正または読み取り不能な場合、ストアは閉じたままで、セッションは続きます。

ストアのパスは、最初にパッチ `store.path`、次に `MEMLENS_STORE`、最後に基本ファイルから決まり
ます。

バックグラウンドのコンパクションにはモデルのルートが必要です。プラグインはモデルを選びません。
例のキー `provider` と `model` がそのルートを与えます。ID は利用するハーネスの LLM ルートから
来ます。provider または model がない場合、各パスはエラー
`The compaction model is not configured. Set provider and model.` で停止します。

各キー、既定値、詳細な例は [設定](../../docs/configuration.md) にあります。

### 権限の規則

メインエージェントはノートをストアに書き込みます。子サブエージェントは代わりに提案を書き込み
ます。プロファイルのスコープの外への書き込みは、人間向けの提案になります。スコープの外の
`forget` は、非表示の提案を書き込みます。

`off` の子はメモリツールもメモリコンテキストも受け取りません。子の提案は子のセッション ID の
下に集まります。親は子の終了時に、提案ごとに 1 行のレポートを受け取ります。

CLI とコンソールだけが修正、秘匿化、承認、却下を行います。ストアは期限切れの提案を人間なしで
却下します。

### バージョン

受け入れる最低バージョンは DeepSeek Harness `0.2.2-rc.3` です。マニフェストは `>=0.2.2-rc.3 <0.3.0-0` を
受け入れます。

## 実装を理解する

<details>
<summary>実装の内部 — クリックして展開</summary>

このセクションは、プラグインがストアと各エージェントのサーフェスをどう保持するかを説明します。
観察できる動作は [このパッケージを使う](#use-this-package) を読んでください。

### 設計

ストアは、すべてのセッションのノートを保持する 1 つの SQLite データベースです。メモリコンテキ
スト、メモリツール、ナッジはストアを使います。このセクションは、これらの部分の集合をエージェ
ントのサーフェスと呼びます。サーフェスをマウントするとは、これらの部分を 1 つのエージェントの
コンテキストに登録することです。

- **ホスト用のストアは 1 つです。** ホストはストアを 1 回開き、すべてのエージェントと共有します。
  プリセットエントリは 1 つのエージェントプリセットに設定を追加し、2 つ目のストアを開始しません。
- **開く操作は失敗できます。** ストアを開くとは、設定を読み、データベースに接続することです。
  ディレクトリの欠落、別プロセスのデータベースロック、不正な設定ファイルは、開く操作を停止し
  ます。プラグインはすべてのセッションを保持し、エラーを返すサーフェスをマウントし、待機後に
  開く操作を再試行します。新しい試行は前の試行より長く待ちます。
- **各エージェントのサーフェス。** ホストとエージェントの両方がエージェントのサーフェスを所有
  し、各登録はエージェントコンテキストで終わります。子サブエージェントはナッジを受け取りませ
  ん。ナッジがメモリの書き込みを求めるためです。
- **開いていないストア。** コンテキストとツールはエラーを返します。保存されたコンテキストセク
  ションがないセッションはメモリテキストを受け取らず、サーフェスはナッジを受け取りません。コ
  ンソールはストアのエラーを表示します。
- **後から開くストア。** プラグインはワーカーを開始し、各稼働中エージェントのサーフェスを再び
  マウントします。利用できないストアで始まったセッションは、後でそのメモリを受け取ります。
- **2 回目のマウントは先に古いサーフェスを削除します。** ホストのレジストリは同じ名前の 2 回目
  の登録を拒否します。失敗したマウントは 1 秒の間隔で少ない回数だけ繰り返すため、一時的な失敗
  でサーフェスを失うことはありません。試行を使い切ったマウントは喪失をログに記録します。コー
  ドとデバッグログは、この 2 回目のマウントをリスポーンと呼びます。
- **ワーカーはトリガーでパスを開始します。** ダーティ範囲がバッチ数に達するとパスが始まります。
  ストアのアイドル時間が切れたときにも始まります。また、作業が待機している間は、開始から 10 秒
  後にも始まります。ワーカーは設定されたルートを呼び、1 時間あたりの呼び出し上限を守り、最近
  のイベントをジャーナルに記録します。
- **コンソールは Remote サービスを使います。** プラグインは Typert サービスがある場合にだけコン
  ソール名前空間を登録します。その後、タブはプラグインの HTTP ルートなしでメモリを読み書きし
  ます。

<a id="model-experience"></a>
## モデルの体験

### システムプロンプト

#### モデルが見るもの

プラグインは各エージェントに、`required: true` と順序 220 でメモリコンテキストを登録します。こ
の順序は組み込みのランタイムコンテキストの後です。ハーネスはテキストをランタイムコンテキスト
メッセージとして書き、テキストが変わったときだけ新しいメッセージを書きます。

テキストは 1 つの `<memory>` セクションで、次の部分を持ちます。

- `<how-to>` はポリシーテキストと `customPromptAppend` の値を保持します。キー `customPrompt` は
  テンプレート全体を置き換えます。
- `<directions>` はプロファイルの最新のスコープごとに 1 行を `[<key>] <age> <summary>` として保
  持します。バジェットより古いスコープは 1 つのキー一覧にまとまります。
- `<here>` はアクティブスコープのフロンティアを保持します。ノートは `#<pos> <date> <body>`、範
  囲は `#<a>-<b> <start>..<end> <summary>` の形式です。

ポリシーテキストは、ツリーの形、2 つの読み取りツール、書き込みの規則を述べます。
[コンテキスト契約](../../packages/core/src/domain/context.ts) がテキストを保持し、
[プロンプト](../../docs/prompts.md) がその場所を示します。

#### トークンへの影響

メモリコンテキストを含む各リクエストに固定のコストがかかります。コストはバジェット `here` と
`directions`、および `customPromptAppend` の値に応じて増えます。

#### KV キャッシュへの影響

メモリテキストはリクエストの先頭のランタイムコンテキストにあります。セッションのターンの間も、
そのセッションの書き込みの間も変わりません。このセクションはセッション全体でプレフィックス安
定です。

プラグインは新しいセッションで、またハーネスが会話をコンパクションするときに、テキストを再び
レンダリングします。テキストはノート、バジェット、カスタムプロンプトが変わったときだけ変わり
ます。

### ツールスキーマと結果

#### モデルが見るもの

エージェントスコープのツール定義です。説明、パラメータ、`src/tools` の応答スキーマを含みます。
各エージェントのツールセットはプロファイルのモードで決まります。

| ツール          | メインエージェント | `propose` の子 | `read` の子 |
| --------------- | ------------------ | -------------- | ----------- |
| `memory_note`   | はい               | はい、提案     | いいえ      |
| `memory_find`   | はい               | はい           | はい        |
| `memory_open`   | はい               | はい           | はい        |
| `memory_map`    | はい               | はい           | はい        |
| `memory_forget` | はい               | いいえ         | いいえ      |
| `memory_review` | はい               | いいえ         | いいえ      |

`off` の子はツールもメモリコンテキストも受け取りません。

各呼び出しはレンダリング済みのテキストを 1 つ返します。表は各ツールのテキストを示します。

| ツール          | モデルが読むテキスト                                                              |
| --------------- | --------------------------------------------------------------------------------- |
| `memory_note`   | `saved <addr>`、または `Proposed to your parent: <body> (proposal <id>)`          |
| `memory_find`   | ヒットごとに 1 行、`<addr>  <date>  <kind>  <body>` の形式、または `No hit.`      |
| `memory_open`   | エントリとその longform、範囲の子ごとに 1 行、または `The range holds no record.` |
| `memory_map`    | スコープごとに 1 行、またはフロンティアの範囲ごとに 1 行                          |
| `memory_forget` | `Done. A target outside the profile waits for a human.`                           |
| `memory_review` | 期限の来たレコードごとに 1 行、または `reviewed <count> records, next <date>`     |

#### トークンへの影響

固定のスキーマコストに加えて、呼び出しごとに 1 つの簡潔な応答があります。親レポートは、子の終
了時に、子の未処理の提案ごとに 1 行を追加します。

#### KV キャッシュへの影響

スキーマは、ツールセットとプロファイルのモードが変わらない間はプレフィックス安定です。呼び出
しとその応答は再利用可能なプレフィックスの後に追加されます。

### ナッジ行

#### モデルが見るもの

プラグインはメインエージェントのツール呼び出しとターンを数えます。上限に達したカウンタは、user
ロールの行を 1 つ挿入します。その行は `{n}` を保持し、そこに回数が入ります。既定のテキストは次
のとおりです。

```text
[memory] {n} tool calls since the last record. Anything durable: a decision, a correction, a preference, a failed attempt and its cause?
[memory] {n} turns since the last record. Anything durable: a decision, a correction, a preference, a failed attempt and its cause?
```

設定の `[nudge]` セクションが回数とテキストを与えます。0 以下の上限はそのカウンタを無効にします。

#### トークンへの影響

上限に達するたびに短い行が 1 つ入ります。ノートの書き込みまたはナッジが両方のカウンタをリセッ
トするため、行はまれなままです。

#### KV キャッシュへの影響

行は再利用可能なプレフィックスの後に追加されるため、それ以前のエントリを無効にしません。

<a id="known-limitations-and-deferred-work"></a>
## 既知の制限と延期した作業

これらの制限は、このパッケージが合わない場合や特別な注意が要る場合を示します。これらは現在の
パッケージの制約であり、作業のバックログではありません。

- **コンパクションには設定済みのルートが必要です。** provider がない、または model がないパ
  スは "The compaction model is not configured. Set provider and model." で失敗します。コンソー
  ルはそのエラーをメンテナンス画面に表示し、影響を受けた範囲は次のパスのためにダーティのまま
  残ります。[設定する](#configure-it) を参照してください。
- **2 回目のマウントは試行回数に上限があります。** プラグインは先に古いサーフェスを削除し、1 秒
  の間隔で再びマウントします。試行を使い切ったマウントは喪失をログに記録し、エージェントは次
  のトリガーまでサーフェスなしのままです。
- **ナッジはメインエージェントだけを数えます。** サブエージェントはナッジを受け取らず、発見を
  記録するリマインダも受け取りません。
- **コンソールには Typert サービスが必要です。** 名前空間はサービスが現れたときにだけ登録されま
  す。Web ゲートウェイのないプロファイルはコンソールを受け取らず、プラグインはエラーを報告し
  ません。

### 開発メモ

```sh
pnpm run build
pnpm run typecheck
pnpm run test
```

リポジトリのルートの `pnpm run verify` コマンドは、ビルドとすべてのチェックを実行します。
